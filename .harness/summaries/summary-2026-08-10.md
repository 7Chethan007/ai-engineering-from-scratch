## Core ideas (revision bullets)
- GPU execution is asynchronous: ops are submitted, Python returns immediately. `torch.cuda.synchronize()` is required before timing, or GPU time reads ~0.
- `.to("cuda")` copies data from CPU RAM to GPU VRAM and costs real time (PCIe transfer) — move data once, not per-op.
- Matmul `a @ b` = `c[i][j] = Σₖ a[i][k]·b[k][j]`; it's the core op of every deep learning layer.
- Memory per parameter: **fp32 4B, fp16 2B, int8 1B, int4 0.5B** → 1 GB / 0.5 GB / 0.25 GB / 0.125 GB per billion params.
- 24 GB VRAM ≈ **12B params in fp16 (inference)**; **~2B params for training** (Adam: weights + momentum + variance + gradients ≈ 12–16 B/param).
- Why the ecosystem exists: quantization + LoRA/QLoRA are direct answers to the training memory wall.
- VRAM budget ≠ weights only: KV cache, activations, and framework overhead all count.
